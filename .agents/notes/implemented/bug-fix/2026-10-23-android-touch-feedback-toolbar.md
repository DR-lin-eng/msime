# Agent Note: Android 字母键触下反馈与工具栏状态底色

Status: implemented

## Problem

字母键的气泡和按压态在按下时出现，声音、振动和可选按键动画却经点击监听等到松手后播放。同一动作的反馈分成两个时刻。工具栏快捷图标清除了系统背景，绘制只区分选中，没有按下底色，主要反馈变成图标缩放和松手回弹。

## Decision

`ImeLetterRows.bindLetterGestures` 把反馈注册到 `KeyboardPressButton` 的触下入口。按钮先执行框架的按下处理，再播放 `ImeKeyFeedback.onKeyDown`；普通字母、滑动选项和长按保留原来的动作判定，按下只反馈，不提前写入文字。

触摸结束后，按钮把已播放反馈的状态保留到框架排队的点击之后。松手仍只计数并执行一次动作，不再重播反馈；取消立即结束当前手势，先前松手已排队的点击仍持有各自的反馈标记。移出窗口使旧清理任务失效。无触摸前导的 `performClick` 沿用点击反馈，服务、气泡和选项的归属规则不变。

`KeyboardShortcutButton` 的描边和实心图标共用最大 40 dp、圆角 12 dp 的状态底块。按下使用当前图标色的轻染色，选中继续使用皮肤强调底色，松手和禁用不留下按下色。工具栏图标保持原位，通过即时底色反馈触摸；字母键继续使用已有按压动画和用户选择的动画。属性动画是否开启交给 `ValueAnimator.areAnimatorsEnabled`，按压路径不再直接读取两项全局设置。

不更改振动强度档位、触屏布局、工具顺序、命中区域或输入引擎；时序问题不能通过任意加大马达幅度解决。

## Existing notes audit

- [振动档位](2026-10-08-keyboard-haptic-levels.md)部分重叠，继续持有硬件能力降级和四档映射，本项只调整字母键播放时刻。
- [中文长按与上滑](../../implemented/feature/2026-10-20-android-letter-hold-variants.md)及[手势设置](2026-10-21-android-letter-option-gesture-settings.md)部分重叠，继续持有松手提交、取消、长按和方向设置，不能为了触下响应直接提交基础字母。
- [工具栏排序](../../implemented/feature/2026-10-15-android-toolbar-order.md)和[撤销重做](../../implemented/feature/2026-10-22-android-toolbar-undo-redo.md)相邻，保留动作、排列和固定两端；本项仅扩展工具栏设备用例观察按压与像素状态。
- React 反馈预览的宿主代次笔记与原生按键时序无关。

## Alternatives considered

- 按下即提交字母最直接减少按下到文字变化的等待，但破坏字母长按、滑动角标、取消和滑行输入的选择边界，故按下只提前反馈。
- 直接缩短或加大三档振动能改变马达输出，但不能使振动与触下同步，也缺少同一真机逐档对照，因此保留现有能力降级与参数。
- 为工具栏增加模糊与更强弹簧动画能显著改变外观，但会增加绘制和动效负担，也没有修复缺失的状态底色，因此采用保持图标位置的轻染色。

## Verification

`ToolbarEdgesDeviceSmoke` 在已安装原生产品中调用真实按钮、手势绑定和反馈入口，观察按下、松手、取消、快速同键连按、禁用及无障碍点击；反馈时间戳只证明入口时机，不代表物理马达延迟。描边和实心图标在相同尺寸下渲染空闲、按下、松手、选中和禁用图像，核对状态恢复及命中区域不变。既有 240/320/600 dp 工具栏固定两端、滚动、排列与计算器检查保留。

同一设备命令分别运行原始生产文件、修改文件和由回滚脚本恢复的独立副本；证据目录保存原始 stdout、stderr、退出状态、源码和 APK 哈希。设备测试声音和马达关闭，因此不声称主观触感、真实编辑器文字提交延迟或全部卡顿已改善。Android 宿主检查、原生 APK 编译、笔记和本地 quick 门禁另行记录实际结果。

## Consequences

字母键的触感、声音、气泡与按压状态更早在同一按下事件回应，工具栏增加即时而稳定的按下底色。按钮增加少量触摸生命周期状态及清理任务，后续调整框架点击或手势分发时必须维护其排队顺序；无障碍、取消和快速连按是回归边界。

用户提供的三星 4.9.00.8 APK 实际是数据迁移组件，未声明输入法服务。REA 包图、manifest 及 DEX 补充解析只能证实该限制，不能作为三星真实键盘按键实现的来源。此实现独立修复水杉已复现的问题，没有复制三星代码或资源；同一实体手机上的手感与端到端延迟对比仍需实际键盘包和硬件。
