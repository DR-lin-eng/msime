# Agent Note: 长全拼未完成尾音节保留完整前缀组句

Status: implemented

## Problem

全拼只在全部音节完整时组合整句。长输入末尾刚打出声母时，完整前缀没有整句候选，只剩词库里的短前缀；开着纠错时字面候选还会被较短的纠错前缀挤出首页。用户看到的表现是长句的后半段中文消失，补完尾音节后又回来。

## Decision

超过现有多切分短串范围的输入，末尾为合法未完成音节且前面全部为完整字面音节时，复用词网格生成完整前缀的候选。候选的拼音和规范读音都只覆盖完整前缀，选择后末尾拼写保留，不把未完成音节当成纠错。短串、无效尾部、非字面的纠错路径和整句开关维持原约束。

纠错主路径与字面回退合并时，仅在存在这种新增的字面前缀整句时复用按覆盖范围稳定合并；同覆盖长度不改变优先级，不比较词频和模型分数。修复属于共享引擎，Windows 与 Android 共同使用，不新增宿主偏好或改变默认值。

## Existing notes audit

检索未完成音节、完整前缀与整句后，[手机辅助码](../feature/2026-10-17-mobile-direct-helpcode.md)持有辅助码触发，和本次字面全拼不同；[数字符号候选](../feature/2026-10-21-number-symbol-candidates.md)持有数字输出，与本次无关。现有跨度缓存和完整整句解码继续复用，不改查询预算或词网格评分。

## Alternatives considered

- 放宽精确词网格查询，让末尾声母直接匹配所有音节，可预测尚未输入的字；但会扩大查库与评分范围，也会改动完整跨度必须精确的约束。因此只组合已经完整的前缀。
- 关闭纠错可以绕过一部分候选被挤出首页的问题，但不能补齐完整前缀组句，也会改变用户设置，因此保留纠错选择。

## Verification

合成词库覆盖自动和手动切分、冷暖缓存、纠错开关、未完成声母被拆分、完整尾音节恢复、无效中段与短串边界。固定生产资源上的同输入 Host API 探针由两项失败变为两项通过，选择后分别仍保留 c、ch。真实 Android/Windows 键盘界面仍需设备验收，容器结果只证明共享候选生成与选择链路。

## Consequences

未完成音节期间多一次有界前缀组句，复用已有跨度与解码缓存；用户得到可选择的完整前缀，继续输入仍可形成完整长句。部分选择会按原有共享运行时规则上屏或暂存，不把末尾未完成字母误记进词条。
