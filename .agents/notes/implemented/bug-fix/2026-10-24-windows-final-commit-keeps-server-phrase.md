# Agent Note: Windows 最终提交使用 Server 的完整词段

Status: implemented

## Problem

Windows 的候选窗和 TIP 分别持有自己的 Runtime。`_SelectHighlightedHostCandidate` 已按 Server 回复定位本地候选，但成功选择后仍把本地 `selected.commit` 写入整个 TSF 组字范围。若本地只交出最后一段，Server 回复中的已选前缀便被丢弃；若 Server 已结束、本地仍返回部分选择，TIP 又会继续显示已结束的组字。原来的回归替身在持有前缀时只返回尾词，却把只提交尾词当成成功，没有检查完整文本。

这与用户反馈的 QQ 长句分段选择后只剩最后一个字一致，但现有日志不包含该次完整提交，尚不能证明真实 QQ 使用的版本和两个 Runtime 分叉的具体起点。真实共享引擎与 Server 的同步合成长句场景本身正常，不能把本修复的替身回归说成 QQ 真机复现。

- [长串未完成音节](2026-10-24-quanpin-incomplete-sentence-prefix.md)：保留；生成前缀和剩余拼音仍由共享引擎决定，不在 Windows 重写算法。

## Decision

无制表符的完整 Server 回复是最终写入文本，里面已包含该会话持有的全部词段。宿主依旧按候选文字在自己的代次里唯一选择，但它的提交文本不再替代完整回复，也不再靠拼接前缀猜测整句。

Server 完成而本地仍留有拼音或词段时，先成功写入完整回复，再取消本地残留并结束 TSF 组字。没有 Server 回复的本地入口继续使用本地提交；含制表符的部分回复仍推进与刷新组字。占位、歧义、未知词、读取失败沿用原边界。

## Alternatives considered

- 直接把本地前缀接到尾词前面，改动少且容易解释。没有采用：本地结果也可能已经带前缀，重复字和重复词不能靠去重猜测；Server 的完整回复已经表达了正确文本。
- 只写 Server 文本而不推进本地选择，能统一显示和提交来源。没有采用：旧笔记已经记录这样会积累旧拼音；本次保留本地选择，仅统一最终写入。
- 按来源把生成句全部强制完成，能少一条分段状态。没有采用：真实 Server 与 TIP 测试已能同步保留生成前缀和未完成音节，强制结束会丢失用户尚未完成的输入。

## Verification

Docker 编译实际 TIP 选词方法，窗口、Host 返回边界和编辑器为替身。合成用例检查完整前缀、相同前缀重复出现、本地提交分歧、Server 完成但本地仍部分选择，以及已有文档内容保持；保留后页、部分回复和拒绝路径覆盖。相同用例运行基线、修改与回滚，字面输出和退出码记录在任务证据中。

另用真实 Host API、ServerSession 和 EngineSessionAdapter 检查长串前缀选择，区分它与替身模拟的分叉情形。QQ 原生编辑器的回归仍需 Windows 安装包验收。

## Consequences

完整上屏与用户所见候选归同一 Server 会话；本地学习和候选选择仍前进。最终完整回复与本地结果有分歧时以完整回复为准，不在宿主重新组句。本改动没有证明或修复两个会话发生分叉的起点，后续若仍能在 QQ 复现，需要该次提交的隐私安全状态诊断。
