# Agent Note: Linux 原生画布播放有界图片动画

Status: implemented

## Problem

[原生 X11 画布](../../implemented/architecture/2026-10-20-linux-native-canvas-x11.md)可以绘制自由挂件，但[共享图片接口](../../implemented/feature/2026-10-20-linux-canvas-image-formats.md)只返回静态图。能够加载 APNG、GIF 和 WebP 不能证明正在播放动画。

固定参考 `msime-windows@dd018f79858314ed542a47c528608752b13bd261` 的 `ui/src/AnimatedImage.cpp`：APNG/GIF 延时先四舍五入到毫秒，不超过 10ms 的值归一化为 100ms；APNG 使用完整播放次数；GIF 没有循环扩展时播放一次，扩展中的非零值表示首遍之后的重复次数；播放结束保持末帧。Windows 的 WIC 多帧 WebP 路径使用固定 100ms 帧间隔并无限循环。

动画重绘虽然复用解码后的图像，但每次仍新建预编辑、序号与候选的 Pango 布局；候选正文的测量和绘制又分别排版。合成十项候选的基线每帧创建 43–83 个布局，快速重绘会反复付出同样的文字塑形开销。

## Decision

保留现有单帧 ABI，另加同步的动画回调接口。共享层负责有界解码、完整画布合成、延时和循环语义，成功验证整张图片后才发布任何帧；C++ 回调捕获分配异常并返回拒绝，异常不跨越 C ABI；宿主复制像素并持有播放状态。继续限制 8MiB 输入、2048 边长、120 帧和 800 万解码像素；宿主对同一包所有不同资源累计像素，不因分别调用接口绕过包预算。

X11 原生窗口以单调时钟和最近的下一帧边界调度，不逐帧读文件或重写 classicui 主题。候选变化、菜单和定位更新不重启动画，换肤或从隐藏重新显示才重新计时；失焦、清空、UI 切换和销毁取消定时器，有限动画播完后也不再唤醒。静态与不支持原生窗口的上下文保留原路径。

### 每帧文字布局

`NativeCanvasX11` 为当前这版内容持有 `NativeCanvasTextCache`：预编辑、辅助行、候选序号，以及普通/选中两种候选文字布局按槽位保存，缓存上限随当前候选数线性增长。动画帧、曝光和悬停只复用布局；按下候选首次需要另一种配色时只创建对应变体。绘制中的文字高度直接读取待绘制布局，序号的测量与绘制也共用一次排版。位图、背景、高亮和前后层挂件仍按当前帧绘制。

内容、配色、字体、缩放或可用宽度变化都经过 `measure()`，先清空缓存；菜单进出同样重排。隐藏与关闭窗口立即释放缓存，不跨会话共享布局，也不改变原有单调时钟与有限动画停止规则。

### 旧笔记审计

- 原生 X11 画布：部分重叠，保留窗口协议、候选身份和回退边界，互链说明新增动画。
- 共享图片解码：部分重叠，旧单帧 API 的默认图语义保持，不能原地改为多次回调。
- [候选皮肤 v2 宿主生命周期](../architecture/2026-10-13-candidate-skin-v2-native-host-lifecycle.md)：部分重叠，沿用隐藏停止与重新显示计时要求；Wayland 和其他面板所有权仍未补齐。
- 其他平台的图片播放笔记：独立宿主实现，不由本次修改取代。

## Alternatives considered

复用单帧 API 并调用多次最少增加符号，但会破坏旧宿主假设和回调所有权，不能采用。

每帧改写 classicui 主题可以复用桌面窗口，却无法稳定表达自由挂件、会触发主题重载和磁盘 I/O，且不解决 Wayland 所有权，因此保留静态回退。

在每个宿主复制解码器和 GIF 循环修正可以减少共享接口变化，但会让帧合成、预算和循环规则漂移；解码与时序归共享层，平台只绘制并调度。

复用整张静态前景位图最能减少文字绘制，但需要拆开挂件层级与半透明高亮的合成，还会额外持有一份随缩放扩大的像素缓存；本次只复用 Pango 布局，保留既有绘制顺序。只复用绘图缓冲可以减少内存分配，却仍会在每一帧重复文字塑形，不能处理已测到的主要布局开销。

## Testing

`linux-candidate-native-canvas` 逐像素比较缓存与即时绘制，覆盖横竖排、两档缩放、动画帧、换行、UTF-8 光标、译文词性配色、选中/按下状态及菜单；同时确认重复帧复用布局、重排后重新创建。Docker X11 基准使用十项合成候选，分别测量 180 次重绘和 60 次候选刷新，保留布局创建次数、线程 CPU 时间与窗口像素哈希；性能数字只代表该容器里的合成负载，不等同于显示器实际帧率。

### 2026-10-21 性能与回归验证

固定 Rust 1.97.1 / Debian 12 Docker 镜像中，以 GCC `-O2` 构建实际 `NativeCanvasX11::Impl::paint()` 路径，在 Xvfb 中轮换原版、优化版和回滚版各三轮。每轮每场景重绘 180 次、刷新候选 60 次；下表是三轮各自线程 CPU p50 的中位数，单位 ms。窗口像素哈希在所有版本和轮次完全一致。

| 场景 | 原版 | 优化版 | 回滚版 | 重绘 p50 降幅 |
| --- | ---: | ---: | ---: | ---: |
| 竖排 ×1 | 3.811 | 1.595 | 2.941 | 58.2% |
| 竖排 ×2 | 7.260 | 4.760 | 7.207 | 34.4% |
| 横排 ×1 | 2.961 | 2.143 | 4.273 | 27.6% |
| 横排 ×2 | 9.035 | 7.986 | 9.870 | 11.6% |

重绘布局创建由每帧 43–83 次降至 0；候选刷新由横排 77 次、竖排 137 次降至 56 / 96 次。候选刷新 CPU p50 在各场景的变化介于慢 2.1% 和快 11.5% 之间，不据此宣称整体输入延迟已改善。原版与回滚版的耗时差异也说明本机负载有波动；这份结果不代表显示器帧率、掉帧率或其他平台的实机表现。

## Consequences

文字缓存增加当前窗口这一版内容及最多两种正文配色的布局对象，隐藏或重排即释放；收益是动画帧与悬停不再重复文字塑形。新增调用方若复用缓存，必须把内容、配色和 Cairo 测量上下文变化纳入失效条件。

[原生画布布局](2026-10-20-linux-canvas-layout.md)另行接入字体与候选几何，资源对象未变时布局刷新仍沿用本篇的动画起点。

动画比静态图持有更多解码像素，双份 RGBA/Cairo 转换有短暂峰值；资源只在换肤时加载，并同时执行每图和每包预算。共享 API 不读磁盘，也不改变 Android 等其他宿主的现有解码路径。Wayland 自由画布、其他 Linux 面板、完整几何材质和声明式进退场动画仍不能由本切片证明完成。

选中条、逐角高亮、悬停与预编辑配色由[原生画布外观](../../implemented/feature/2026-10-20-linux-canvas-appearance.md)补充，保留本篇其余范围与生命周期规则。


新版 `NativeCanvasChrome` 与 canvas 皮肤入口共用当前内容代次的文字缓存：候选正文、序号、普通/高亮释义以及预编辑片段按槽位保存。上游的行揭示、卡片变换、投影、卷轴网格和装饰候选继续按帧绘制；换内容、配色、布局或隐藏时清空。缓存逐像素回归同时跑 chrome 与皮肤、横竖排、1x/2x 缩放及悬停/按下变体，防止同步时悄悄恢复逐帧塑形或改变画面。
