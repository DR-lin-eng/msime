# Agent Note: 本机自适应神经排序与设备优先推理

Status: implemented

## Problem

现有个人模型只比较二元和三元计数，冻结的神经句子模型不会随个人选词训练。词网格把上下文固定截为 64 字；运行时还把本地和云端共用一个 1024 字节窗口。已有神经推理没有设备后端。

## Decision

在共享引擎中增加固定非线性特征网络和在线学习的个人排序头；直接重放已有词对日志，不新增原始输入文件、账号状态或联网训练。日志恢复最多训练 512 条高频词对，每条聚合日志最多训练 16 步，模型、负例池、比较条数和上下文有固定上限。冷启动、学习关闭、非拼音候选和固定首选保留既有规则。

本地上下文单独保留最近 512 个 Unicode 字符，云服务窗口仍为 1024 字节。窗口先删过期前缀再追加新提交，避免在满窗口下为立即丢弃的旧文字扩容。固定交叉特征的散列槽位与符号在编译时生成；训练和推理跳过零乘积，但非零项的浮点累加顺序保持一致。冻结句子模型按实际位置容量和候选长度取稳定窗口，不伪称扩大预训练模型的位置嵌入。

固定特征网络可由宿主提供的 ONNX Runtime 1.23+ 执行。设备初始化在后台运行，不阻塞击键；设备忙时同样回 CPU。自动模式依次尝试 NPU、GPU，注册或执行失败回退同权重纯 Rust CPU；没有运行时不下载、不阻断输入。设备会话禁止节点静默回退 CPU；报告已建立的执行提供者，不把 Docker 的 CPU 验证称作真实设备加速证明。

## Existing decisions

## Alternatives considered

- 完整微调预训练 Transformer 能直接适应更丰富的语言规律，但会扩大键盘扩展内存、训练延迟和模型保存边界；先使用有界个人排序头，并复用现有日志恢复学习状态。
- 只扩大 64 字常量改动很小，但模型位置容量不会随之变大，还可能让前缀缓存每键失效；本地自适应模型用 512 字，预训练模型继续尊重实际容量。
- 各宿主分别实现 CoreML、NNAPI 和 GPU 能使用原生 SDK，但会复制权重和回退逻辑；共享 Rust 层统一 ONNX 执行提供者，宿主只负责提供可选运行时。

## Consequences

合成输入对照中，原版经过 64 轮选择后，在 101 字上下文的首选仍为「丙」；自适应模型首选变为「丁」，关闭个人上下文后恢复「丙」，重开日志后保持「丁」。固定首选不被神经评分越过。模型每个日志固定占用头部、负例池和 512 字窗口，不新增持久化文本格式。新增依赖许可证经六个平台原生打包入口分发。

固定随机特征网络的表达能力有限，不能宣称每次输入都变准确。设备模型很小，初始化和搬运开销可能超过 CPU；初始化在后台，未就绪或设备忙时直接使用 CPU。真实设备的 NPU/GPU 命中与效率需单独测量。不同日志聚合顺序可能产生不同头部权重；恢复时最多训练 512 条高频词对，低频个性化可能需要继续选词才能恢复，不保证浮点权重逐字节一致。若实际语料收益不足，重访特征网络和训练样本选择，不扩大词网格搜索预算来掩盖排序问题。

## Verification

固定 Rust 1.97.1、ONNX 1.23.2 和 ONNX Runtime 1.24.4 的 Docker 环境中，以普通用户运行：`cargo test --locked -p msime-engine -p msime-input-runtime` 通过 2388 项引擎测试、3 项集成测试、31 项 golden 与 327 项运行时测试；49 项既有测量测试忽略。`cargo clippy --locked -p msime-engine -p msime-input-runtime --all-targets -- -D warnings`、格式检查与纯 CPU 的 `--no-default-features` 检查通过。

真实 ONNX checker 接受固定图；ONNX CPU 与 Rust 固定网络的数值测试通过。缺少运行时的独立进程仍通过学习、重开、学习关闭与固定首选的三项集成测试。删除日志重建个人排序头、失焦和清空时丢弃长上下文均有回归。首次以 root 运行的四项权限测试失败；以普通用户重跑全部通过，没有修改测试基线。

复现入口为 `scripts/test-adaptive-prediction-docker.sh`。本机 `cargo` 因 Homebrew `libgit2` 引用的 `libllhttp.9.4.dylib` 缺失无法启动，因此 Rust 验证均在 Docker 完成。仓库 quick、补丁重建与回滚证据在交付记录中保留；未把 Docker CPU 结果当作设备加速或原生宿主装机证明。
