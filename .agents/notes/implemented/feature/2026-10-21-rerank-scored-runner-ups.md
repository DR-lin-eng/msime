# Agent Note: 让候选次选沿用已有的混合评分

Status: implemented

## Problem

`rerank_pick` 已为前九条完整读法计算混合评分，却只返回第一名的位置。首选已经正确、模型更喜欢的次选在第四条读法时，运行时会保持旧次序，随后只保留前三条整句读法的呈现规则把这条次选挪到尾部。模型已有的次选信息没有进入推荐页。

## Decision

保留等权静态/神经评分、九条评分预算及全部来源约束；共享的 `RerankPlan` 保存紧凑排序计划，将已评分整句读法稳定排序后交给既有呈现规则。原生 runtime 和网页调用同一计划，并对候选文字、注释、静态证据和实际选词位置应用同一排列。无完整静态证据时继续使用原来的单首选提升逻辑，不增加模型推理。

## Existing decisions

[静态证据](../../implemented/bug-fix/2026-10-14-rerank-static-evidence.md)部分重叠，继续保留逐字自然对数、等权混合和全有或全无回退；本片仅扩展分数的使用范围。[候选排列](../../implemented/simplification/2026-10-12-runtime-candidate-order-application.md)继续负责并行元数据一致性。[混合权重试验](../../rejected/feature/2026-10-21-rerank-mixture-calibration.md)已否决，不把其参数混入本片。

## Alternatives considered

只调混合权重最少改动，但两组预先声明的参数均降低开发半首选正确数，已恢复等权。保留更多整句读法可提高覆盖，却已有扩大路径导致首选退化的记录，也会挤占短词候选；本片只重用已有九条评分，不改候选数或保留条数。构造整张候选列表的排列最易接入，但列表可很长；只保存九条位置和局部排列，避免每次重排分配整表索引。

## Verification

原始生产实现运行新增合成回归失败，报「首选未变时，次选也应按已有混合评分更新」；新实现通过。该回归确认首选仍是合成甲词，评分更好的第四条读法进入第二位，代码、注释、位置、静态证据与引擎座位同步，重复落定稳定，选择第二位提交实际合成乙词。另覆盖 AI/目录行保持原槽、同分稳定、缺证据回退、九条预算和 128/129/1024 行时分配不随列表增长。

固定 `dict-v2.0.24` 资源、键盘句子模型、学习关闭，无 settled 模型，原版与改版保留独立 release 二进制。没有修改金标准、质量基线和资源锁。下表按同输入逐例比较，不是旧基线 JSON 与新输出相减：

真实网页模型测试同时确认首选的标点/空格提交和次选点击：冻结手写句 `s-052` 的正确读法从原第 185 位进入第二位，点击后提交展示文字。原生合成回归同时覆盖第二位的实际引擎选择。普通用户 Docker 中引擎 2,381 项、runtime 329 项、网页 routing 61 项及 golden 31 项通过；Host API 首轮两项相对路径夹具因只读源码没有可写祖先失败，补齐同一源码的只读临时目录挂载后两项通过。原有资源可选测试和 ignored 的边界保留，不称为全平台设备验收。

### 逐键延迟与门禁

编译、质量评测与单测结束后，在同一 Docker 环境交替运行原版和优化版三轮，按轮次切换先后顺序。全拼用 60 条手写句、每臂 1,320 键；九键和十四键用 81 条合成句、每臂 1,791 键；各舍弃 5 条预热用例。下表为三轮每键均值和 p95 的中位数，单位 ms：

| 键面 | 均值前→后 | p95 前→后 | 16 ms 门禁失败轮数前→后 |
| --- | ---: | ---: | ---: |
| 全拼 | 1.09→1.08 | 4.69→4.67 | 0→0 |
| 九键 | 6.27→6.45 | 15.36→15.98 | 0→1 |
| 十四键 | 4.23→4.25 | 13.87→13.90 | 0→0 |

全拼与十四键均通过三轮 16 ms 的 p95 门禁；九键原版三轮通过，改版第二轮 p95 16.14 ms、退出 1，其余两轮 15.67 / 15.98 ms。九键 p95 中位数增加 0.62 ms 是本次测得的成本，不把它说成无性能代价，也不通过扩大预算或新增已知失败豁免隐藏这一轮失败。该程序只测引擎与重排，不含 IPC 和候选绘制，不能等同于设备上的帧率。

`cargo fmt --all -- --check`、三 crate 全目标 `cargo clippy -- -D warnings`、完整 `verify-local.sh --quick` 和笔记三门禁通过。quick 在此 Docker 内实际运行 Rust 工作区、Linux 设置外壳与 Linux 原生门禁；Android、Wasm 目标、HarmonyOS、Windows、macOS 与 Apple 桥接因缺本平台工具链或已配置构建而跳过。Host API 的两项相对路径环境错误已单独同二进制复测通过。没有修改质量基线或 `known-failures.txt`。

同一 `ROLLBACK.sh --recommendation` 在独立副本恢复上一确认提交的代码，哈希与原始记录一致；强制重编后的回滚 `convert_eval` 与原版二进制 SHA-256 相同，八组准确率 JSON 与完整候选 JSONL 逐字节相同。审阅补丁随后在原始副本重新应用，优化代码保持最终状态。

## Consequences

收益是已算出的次选分数可以进入推荐页，不增加评分候选数或模型推理；代价是次选排序改变，存在上述前五退化，且每次实际排序需要九条以内的稳定排序与并行交换。保持原 `rerank_pick` 接口的单首选行为供已有调用方使用，runtime 与网页使用新的 `rerank_plan`；来源和证据规则仍只有共享层一份。关闭模型或证据不完整时不启用新混合次选次序。首选尚未提升，未覆盖读法和词典覆盖仍需后续处理。
