# Agent Note: 移动端触点概率纠错

Status: implemented

## Problem

移动端字母键误触相邻键后，引擎只能按固定代价猜测。键中心的明确输入与靠近边界的输入受到同样的纠错，既可能误纠，也浪费展开预算。Android 原生宿主使用 Java，按键经 JNI、Host API 与 input-runtime 进入共享 Rust 引擎；本仓库不以内嵌 Fcitx5 核心处理移动输入。

## Decision

保留原按键接口，增加一次按键范围内有效的可选触点旁路。坐标相对命中键中心，以键宽归一化；键盘同时传递实际相邻键中心，兼容键距、高度、分离式键盘和布局缩放。组字请求按原始 ASCII 字节维护可空坐标，普通按键和分隔符没有坐标。

共享引擎使用二维高斯模型计算自己和邻键的概率，以 `-6 ln(p)`（最低 1）替换有证据的固定代价，低于 2% 的方向不展开。标准差为实际横、纵键距的 0.35；键中心半径为键宽的 0.22。几何邻域按实际横纵键距筛选，避免高键帽丢掉跨行邻键，也避免跨过分离式键盘中间的空白。

全拼阶段 2 的 k-best 切分和合法音节纠错整句都读 `QueryRequest::touch_points`。双拼纠错整句按原始两键编码计算概率，不把全拼声韵母的字母下标当触点下标。全中心输入在初始化纠错表之前返回；局部中心片段在读取变体表之前跳过。没有触点的请求保持旧行为、排序和变体缓冲大小。

`msime_client_character_with_touch` 把字符和 a..z 的 52 个相对中心坐标放在同一次 Host API 调用内，旧字符接口保持不变。input-runtime 的动作枚举不增加字段，只在真正调用引擎字符入口前设置旁路，调用后清除，避免自动提交或模式编排消耗样本。非法或缺失几何在派发前拒绝，不改变组字。

触点只保存在本次组字内存，不持久化、不进入日志或在线请求。解析、整句与双拼辅助码答案随触点变化失效，原始词库行继续复用。光标编辑使用明确字节位置维护坐标，部分提交保留原文后缀，普通键和分隔符填 `None`，任意外部替换丢弃无法证明对应关系的证据。取消、结束与换方案清空状态。句中辅助码会把标记和辅助码从双拼查询串移除；该模式暂不投影触点，清空坐标并沿用无触点排序，避免后续字母的几何错位。取消组字后重新采样，普通双拼与全拼触点纠错保持可用。

Android 在字母触下时采样；空隙路由后先还原真实坐标。取消、长按和滑行接管清除样本，点击回调只在该键的真实触摸仍有效时使用样本，无障碍点击走普通字符路径。实际按键中心来自 View，重复的分离式 G 键只取最近的一份。

## Alternatives considered

直接改造按键事件能够一次携带所有信息，但会迫使所有平台和事件消费者一起迁移。可选旁路只影响支持触点的宿主，且不引入 Fcitx5 依赖。

固定 QWERTY 几何最简单，但行高、键距与分离式布局会使跨行概率错误，因此由 View 提供实际邻键几何。

## Testing

Docker 使用固定 Rust 1.97.1 与同一合成词库、同一探针比较基线、修改与回滚。单测覆盖概率归一化、方向性、中心门控、非法几何、高键帽跨行、分离式布局、重复字母光标插删、部分提交、普通按键回退、换方案、会话隔离与触点缓存失效。同步后的补充回归覆盖反引号、分号辅助码触发时丢弃未映射几何，以及新组字恢复采样。C ABI 单测验证错误参数不派发以及后续普通输入仍正常。Android 宿主门禁通过 JNI 编译、256 项 JVM 冒烟和 215 个设备测试源编译。

## Consequences

高斯尺度是保守初值，不代表真实用户数据校准。当前只给 Android 26 键拼音输入采集离散触点；其他宿主可以复用新增的可选接口。九键、滑行和其他语言保持原路。字母采样多了实际键几何和组字内存，触点变化会淘汰组装后的答案缓存；中心门控减少无依据的搜索。容器测试和原生源编译不等同于模拟器或真机验收，本机未发现可运行的 Android SDK/AVD。
