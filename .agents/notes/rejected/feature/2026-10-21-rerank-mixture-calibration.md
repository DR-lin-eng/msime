# Agent Note: 用保留语料校准候选混合评分

Status: rejected — 两组预先声明的权重均降低开发子集首选正确数

## Problem

共享 `ordering::rerank_pick` 将词网格静态逐字分与神经逐字分等权相加。静态分包含词频、切分和分词启发式，并非已校准的完整语言概率；两侧同为自然对数不能证明等权最准确。既有冻结评测允许检验首选质量，但不能根据单个例子或总分波动就改权重。

## Proposal

保持候选来源、九条比较预算、词典首选豁免、纠错权限、逐字归一和相同分稳定顺序，仅校准已有混合权重。先按固定 case ID 的 SHA-256 首字节奇偶将中性句集分成开发与保留两半；只用开发半比较原来的 0.5 与 0.35、0.65，选定后再查看保留半及其他冻结集合。不改金标准、资源锁或已有质量基线。

## Existing decisions

[静态证据](../../implemented/bug-fix/2026-10-14-rerank-static-evidence.md)部分重叠：继续保留证据传递、逐字自然对数、全有或全无回退和来源约束。等权是否保留由独立对照决定。 [上下文预算](../../implemented/bug-fix/2026-10-16-rerank-context-budget.md)继续只为实际九条比较候选留空间。[扩大路径试验](../../rejected/bug-fix/2026-10-14-lattice-rerank-path-coverage.md)已有首选率退化证据，不重做。

## Alternatives considered

完整重排全部次选可以让模型偏好的次选靠前，但不会直接提高既有首选决策，还要同时改变原生与网页的排列契约，先校准当前首选规则。按上下文长度增加启发式开关可以区分输入场景，但缺少独立的分组证据，不先加额外阈值。扩大候选范围能恢复被剪枝的正确答案，已有试验却显示首选率下降并增加推理，沿用现有预算。

## Acceptance criteria

开发半有收益后才查看保留半；正式前后独立二进制覆盖三份句子、全拼词、九键词句及十四键词句。逐例报告改对、改错和候选集合变化，不只报告汇总首选率。运行 Rust 回归、格式、clippy、quick、笔记门禁和同输入回滚，另外量化逐键延迟。

## Risks

冻结中性集是引擎难例分布，收益不能外推为自然行文总体准确率；短词、九键和十四键可能呈现不同取舍。若开发收益不能在保留语料复现，则恢复原权重并继续定位具体排序缺口。

## Evaluation and rejection

固定中性集按 ID 的 SHA-256 奇偶拆为 547 条开发样例和 558 条保留样例。开发半原等权首选 400/547，神经权重 0.65 为 396/547，0.35 为 397/547；两组均无首选收益，不查看其保留半以继续选参。生产评分恢复为 0.5，没有修改语料、基线或资源。后续只检验[已评分次选次序](../../implemented/feature/2026-10-21-rerank-scored-runner-ups.md)这个独立机制。
