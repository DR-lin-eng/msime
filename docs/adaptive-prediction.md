# 本机自适应预测

拼音和双拼的同长度词典候选在开启「学习」与「个人上下文」后，使用既有词对记录训练轻量神经排序头。九键对消费同一段数字的词典候选复用同一模型。样本不足时沿用现有词频和 n 元排序；固定首选、非拼音方案、补全和部分输入不跨界比较。每次选择只增加本地统计，不保证每次预测都更准。

本地预测保留当前焦点最近 512 个 Unicode 字符，失焦和清空上下文时丢弃。个人数据清理、删除词条后重建排序头；重启从既有个人日志中的最多 512 条高频词对恢复排序头，其余个人计数完整保留，后续选词继续在线训练。云候选仍只接收原有 1024 字节窗口。已有句子 Transformer 的位置容量不变，按模型实际容量取稳定尾部窗口。

默认编入设备推理适配；没有兼容 ONNX Runtime 或没有设备提供者时，自动运行同权重纯 Rust CPU。仅 CPU 的嵌入构建可用 `cargo build -p msime-engine --no-default-features`。Wasm 不依赖 ONNX Runtime。

宿主可通过进程环境指定：

| 变量 | 值与作用 |
| --- | --- |
| `MSIME_PREDICTION_DEVICE` | `auto`（默认）：先尝试 NPU，再 GPU，最后 CPU；`npu` 或 `gpu` 限定尝试类型，失败仍回 CPU；`cpu` 强制 CPU |
| `MSIME_ONNX_RUNTIME` | 宿主所提供的兼容动态库绝对路径；未设置时按系统库名查找，不下载 |

Apple 使用 CoreML 的 Neural Engine 或 GPU 计算单元，Android 使用禁用 CPU 设备的 NNAPI（实际为 NPU 或 GPU），Intel 设备可使用 OpenVINO NPU/GPU，Windows 可用 DirectML，NVIDIA 设备可用 CUDA。库需自带对应提供者，单有硬件不等于当前运行时支持它。`msime_engine::adaptive::prediction_backend()` 返回建立成功的执行提供者；执行错误会丢弃设备会话并回退 CPU。

固定特征网络仅 32 KiB 权重，每次最多比较 16 条。它不向云端传送原始输入，不下载或保存额外模型文件。设备初始化在后台执行，初始化期间及设备忙时使用 CPU；数据搬运仍有成本，实际效率需要在目标设备测量，不能由 Docker CPU 数据推断。

Docker 回归：`scripts/test-adaptive-prediction-docker.sh`。包括在线学习、超过 64 字的上下文、重开、固定首选、学习关闭、清理数据、ONNX 与 CPU 数值对照和缺少设备时的回退。

## 充电夜间学习与验证码

「隐私 → 本机」增加「充电夜间自学习」和「短信验证码提示」。夜间学习默认开启，仍同时受原有学习开关和无痕模式约束。系统任务要求充电、电量不低且空闲，共享层复查本地 0–6 点；每天最多成功训练一次，输入会话正在使用词库时推迟。每轮最多重放 512 个已学习词对，做八轮有界训练。数值排序头写在个人 SQLite 日志的 `personal_neural_model` 表中，绑定当前词对散列；继续学习、删除和清空后不使用过时缓存。断电或系统停止任务时请求取消。调度由系统决定，不保证整点执行。

剪贴板沿用现有历史开关，开启后自动读取和记录普通文本；键盘冷启动或实时开关到达后，按已有剪贴板身份补读当前内容，已删除条目不重复写回。系统敏感标记、无痕或不允许学习的输入框仍阻止捕获。带明确验证码语义的自动捕获消息只进入短时提示，不写剪贴板历史。

短信提示默认关闭，用户打开后申请 `RECEIVE_SMS`，只接收新短信，不申请 `READ_SMS` 或查询历史短信。短信正文只用于本机识别，单个 4–8 位数字码在内存保留五分钟；提示出现在空闲键盘工具栏，点击才直接交给当前输入连接。该填入路径不经过候选学习、输入统计或模型上下文。关闭授权、关闭对应功能或进入隐私输入状态后不再提供。开关沿用 Android 本机设置的原子文件，设置进程与 `:ime` 进程能观察到同一份值。

### Apple 原生宿主

iOS 的「设置 → 隐私 → 本机数据」和 macOS 的学习设置提供「充电夜间自学习」和「验证码粘贴提示」，两项开关均只保存在本机。iOS 主应用用 `BGProcessingTaskRequest.requiresExternalPower` 请求后台窗口，复查 0–6 点、充电、低电量、无痕和学习状态；键盘扩展不启动常驻训练。macOS 原生输入法用 `NSBackgroundActivityScheduler` 调度，复查接通电源、至少空闲一分钟、夜间和低电量状态。两个宿主都使用同一 Rust 训练门禁与词库维护租约，成功后当天不重复训练。系统可能延后或不执行，不能保证每夜运行。

Apple 不向第三方键盘开放短信收件箱。iOS 剪贴板面板的「使用系统验证码」切换输入方式，自动填充由系统键盘提供；「粘贴验证码」只在明确点按后读取粘贴板，支持带验证码语义的消息或单个 4–8 位数字串。识别后再点「填入」才插入原文本连接；文档身份变化、无痕、禁用提示、面板关闭或五分钟到期会阻止填入。此路径不写历史、不训练、不计输入统计，粘贴仍受系统权限约束。

macOS 在剪贴板历史开启时只观察新复制的文字；安全输入、密码管理器的敏感标记、失焦或组合输入中不展示提示。具有验证码语义的单个数字码显示为不抢焦点的「填入验证码」按钮，点击时再检查当前客户端、开关和五分钟期限，只消费一次。原生账号验证码框标注 `.oneTimeCode`，由系统自动填充；不读取 Messages 数据库或通知正文。

共享纯识别 C ABI 为 `msime_client_input_assistance`，无需词库或键盘会话。自动监视必须包含验证码语义；只有用户明确粘贴时才能用 `allow_plain_digits` 识别纯数字。普通剪贴板文本仍沿用原有历史开关和存储。

### 验证

设备验证使用专用 API 28 AVD：`platforms/android/tests/device/assistance/build.sh` 构建独立准备包，在应用 UID 下验证夜间模型持久化与充电/空闲任务约束；准备包支持 `-e restore true` 恢复设置。外部合成编辑器的 `msime_test_clipboard` 参数会先建立文本输入连接，再发送系统复制事件，避免 instrumentation 停止输入法进程或 inputType=0 的过渡帧干扰验证。完整原生回归仍运行 `platforms/android/tests/device/smoke.sh emulator-5566 --core`。

Apple 验证针对原生产品：iOS App 和键盘扩展在 iOS 26.5 专用模拟器构建、安装并启动，UIKit 测试验证明确读取、二次填入、隐私门禁及验证码排除历史；macOS 原生输入法构建、AppKit 隔离粘贴板测试验证提示、一次填入、过期、失焦和敏感标记。后台请求的编译和共享充电门禁已验证；整夜真机调度、系统收到真实短信后的自动填充和设备 NPU/GPU 性能仍需目标硬件验证。
